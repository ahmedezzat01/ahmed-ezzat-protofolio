1 نظرة عامة على المشروع

1.1 ما هو هذا المشروع؟

هذا المشروع هو موقع Portfolio احترافي متعدد الصفحات متخصص في مجال الأمن السيبراني (Cybersecurity). تم بناؤه باستخدام إطار عمل Next.js 15 مع لغة TypeScript، ويتميز بتصميم داكن احترافي بألوان أسود وأبيض وأحمر (#df2531).

1.2 الأهداف الرئيسية

  • عرض مهارات وأعمال Ahmed Ezzat في مجال الأمن السيبراني
  • توفير أدوات أمنية تفاعلية مجانية للمستخدمين
  • محاكاة واقعية لبيئة الويب المظلم لأغراض تعليمية
  • تقديم مساعد ذكاء اصطناعي للإجابة على الأسئلة الأمنية
  • إنشاء مركز معرفة شامل للأمن السيبراني

  • جرب الإشعارات: في أسفل يمين الشاشة، يغلق المحادثة عند الفتح
  • التمرير للأعلى: يعود للأعلى تلقائياً عند إعادة تحميل الصفحة
  • تصميم متجاوب: يعمل على جميع الأجهزة (موبايل، تابلت، ديسكتوب)
  • وضع ليلي فقط: الموقع مقفل على الوضع الداكن (لا يوجد toggle)
  • لغة إنجليزية فقط: تم إزالة التبديل بين اللغات

9 تحليل الثغرات الأمنية واختبارها

9.1 الثغرات المكتشفة خلال المراجعة

ثغرة 1: تسريب مفاتيح API في الكود المصدري

الشدة: حرج (Critical)

الموقع: app/api/ask-ai/route.ts و app/api/check-breach/route.ts

الوصف: جميع مفاتيح API (NVIDIA, Kimi, OpenRouter, Ollama) مكتوبة بصرياً في الكود المصدري. إذا تم نشر الكود على GitHub عام، يمكن لأي شخص استخدام هذه المفاتيح.

التوصية: استخدام متغيرات البيئة (Environment Variables) بدلاً من الكود الثابت.

الحالة: المشروع موجود على GitHub عام (ahmedezzat01/ahmed-ezzat-protofolio) - المفاتيح مُسربة.

ثغرة 2: عدم وجود Rate Limiting على API Routes

الشدة: عالي (High)

الموقع: جميع API Routes (/api/ask-ai, /api/check-breach)

الوصف: لا يوجد حد لعدد الطلبات. يمكن للمهاجم إرسال آلاف الطلبات واستهلاك رصيد API أو إبطاء الخادم.

التوصية: إضافة rate limiting باستخدام Upstash Redis أو middleware مخصص.

ثغرة 3: XSS محتمل في عرض النتائج

الشدة: متوسط (Medium)

الموقع: SecurityTools.tsx - عرض أسماء الثغرات

الوصف: أسماء الثغرات من API تُعرض مباشرة في الواجهة. إذا كان API مصاباً، يمكن حقن أكواد JavaScript.

التوصية: تنظيف المدخلات (Input Sanitization) قبل العرض.

ثغرة 4: CORS غير مُعرّف

الشدة: متوسط (Medium)

الموقع: جميع API Routes

الوصف: لا يوجد إعداد CORS صريح. بشكل افتراضي، Next.js يسمح الطلبات من نفس الأصل فقط، لكن الأفضل تقييده صراحةً.

التوصية: إضافة headers CORS صريحة.

ثغرة 5: استخدام HTTP بدلاً من HTTPS في IP Lookup

الشدة: منخفض (Low)

الموقع: SecurityTools.tsx - IPLookup function

الوصف: طلب http://ip-api.com بدون تشفير. يمكن ل中间者 اعتراض البيانات.

التوصية: استخدام https://ip-api.com.

9.2 اختبار ثغرات الويب المظلم

لا توجد ثغرات حقيقية في المحاكاة

  • جميع البيانات محاكاة ومولّدة محلياً (client-side)
  • لا يوجد اتصال حقيقي بأي شبكة مظلمة
  • جميع الروابط تستخدم نطاق .sim بدلاً من .onion
  • جميع عناوين IP خاصة (10.0.0.x) بدلاً من عناوين حقيقية
  • لا يوجد نقل بيانات للخارج
  • زر طوارئ (Panic Button) متاح دائماً

9.3 اختبار XSS

النتيجة: لا توجد ثغرات XSS واضحة. جميع المدخلات تُعرض عبر React الذي يقوم بـ escaping تلقائي.

9.4 اختبار CSRF

النتيجة: API Routes تستخدم POST و GET. لا يوجد forms تقليدية تحتاج CSRF tokens. الخطر منخفض.

9.5 اختبار SQL Injection

النتيجة: لا يوجد قاعدة بيانات مربوطة بالموقع. جميع البيانات محاكاة. لا توجد ثغرة SQL Injection.

9.6 اختبار Authentication

النتيجة: الموقع لا يحتاج مصادقة. جميع الصفحات متاحة للجميع. هذا مقصود لأنها portfolio site.
